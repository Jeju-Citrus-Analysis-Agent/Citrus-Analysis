# 팀 중간 검증 안내

## 실행

저장소 루트에서 `python -m pip install -r citrus_freellm/requirements-ui.txt`로 설치하고
`python -m streamlit run citrus_freellm/web.py --server.address 127.0.0.1 --browser.gatherUsageStats false`로 실행합니다.
브라우저의 http://127.0.0.1:8501 에서 질문하세요. Windows에서는 start-web.cmd도 사용할 수 있습니다.
키·공급자·서버 설치본은 포함하지 않습니다. 모델 기능을 쓰려면 .env.example을 .env로 복사해
자신의 서버 주소와 통합 키를 설정하세요. 기존 .env가 있으면 덮어쓰지 마세요.

## 모델 없이 먼저 확인

1. **어떤 품종이 면적당 매출이 높나?**
   하우스온주 약 2.2억원/ha·노지온주의 4.6배, 비용 미반영이라는 설명이 나와야 합니다.
2. **언제 팔면 비싼가?**
   노지온주 5개 시즌 범위와 10월/12월 비교, 2월 가격이 12월의 1.0~1.8배였다는 설명,
   저장비·손실을 고려해야 한다는 한계가 나와야 합니다.
3. **생산량이 늘면 가격은? / 날씨는 영향이 있나?**
   공개 분석의 관측 관계를 설명하고, 인과·미래 가격으로 단정하지 않아야 합니다.
4. **판매량 1000kg, 단가 4000원, 총비용 300만원, 단가 10% 하락 시 이익은?**
   매출 400만원 → 360만원, 이익 100만원 → 60만원, 손익분기 3,000원/kg입니다.
5. **그럼 단가 20% 하락이면?**
   최초 단가 4,000원 대비 20% 하락으로 이익 20만원입니다. 변동률을 중복 누적하지 않습니다.
6. **리포트 만들기 → 전체 결과 → 다운로드**
   HTML·Markdown·JSON에 선택한 성공 결과와 근거·조건이 들어가야 합니다.
   범위를 먼저 선택하고 리포트를 생성하세요.

## 모델 연결 후 확인

```text
2019년과 2020년 천혜향 생산량 비교
그러면 2018년은?
생산면적은?
둘 다 알려줘
```

첫 답변은 18,044톤 → 18,614톤, +570톤/+3.16%입니다.
후속 질문은 품종·연도를 이어받고 지표를 전환해야 합니다. 새 대화 뒤에는 조건을 물어야 합니다.
2016~2017년 생산면적 비교는 값은 보여도 통계 단절을 가로지르는 증감률을 만들지 않아야 합니다.

## 팀원이 판단할 사항

- 질문의 의도와 적용 품종·기간이 맞는지, 추가 확인이 적절한지
- 근거 설명이 질문에 답하는지, 단순 수치 조회·가정 계산과 구분되는지
- 설명 길이와 표·리포트가 이해하기 쉬운지
- 준비된 문장 외의 표현, 지표 전환, 잘못된 단위, 실패 후 재질문에서도 기대대로 동작하는지

재현할 질문과 이전 대화 순서, 실제 답변, 기대 답변을 함께 기록해 주세요.
현재 설명은 등록된 다섯 주제에 제한되며, 원자료로 분석 문서 전체를 재현한 검증은 아닙니다.

## 자동 검사

`python -m unittest discover -s citrus_freellm/tests -v`

기존 조회 회귀·변조·정의·계산·출처 검사와 UI 대화/초기화/다운로드/세션 분리/오류 처리를 검사합니다.
모델 응답은 모의 응답을 사용하며 API 호출하지 않습니다. UI 의존성이 없으면 UI 검사 5개는 건너뜁니다.
실제 모델 검사는 `python -m citrus_freellm --diagnose`와 위 대화로 별도 확인합니다.

공유 전 결과: 이 패키지의 152개 검사를 통과했습니다. Windows의 자동 줄바꿈 변환을
적용한 Git 체크아웃에서도 근거 해시가 유지되는지 검사합니다.
기존 저장소 tests는 별도로 실행해 32개 통과·2개 건너뜀·11개 실패였습니다.
실패는 로컬에 없는 Git 제외 가격·유통 CSV를 요구하는 test_load_processed 사례입니다.
기존 src·tests·data는 변경하지 않았고 누락 자료를 가짜 값으로 채우지 않았습니다.
