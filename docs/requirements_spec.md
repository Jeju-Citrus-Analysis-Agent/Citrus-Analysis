## 1. 프로젝트 개요

### 1.1 목적
제주 감귤 농가와 예비 농업인(사업자)이 **생산량, 유통·도매시장 가격, 기상·병해충 같은 환경 변수**를 근거로 의사결정을 내릴 수 있도록 데이터 분석 도구와 질의응답 에이전트를 만든다.

### 1.2 대상 사용자와 핵심 질문
| 사용자 | 핵심 질문 예시 |
| --- | --- |
| 기존 감귤 농가 | "올해는 언제, 어느 도매시장으로 출하해야 단가가 높을까?" |
| 예비 창업자 | "노지온주와 하우스·만감류 중 어떤 품종이 면적당 수익이 좋을까?" |
| 분석가(본인) | "가격 변동을 설명하는 핵심 변수는 무엇인가?" |

### 1.3 범위
- **포함:** 제주 감귤(노지온주·하우스온주·월동온주·만감류)의 생산·유통·가격 분석, 시각화, 간단한 예측, 리포트 생성
- **제외:** 실시간 경락가 수집, 웹 서비스 배포, 유료 외부 API·LLM 연동 (NFR-01)

### 1.4 개발 환경
| 구분 | 내용 |
| --- | --- |
| 언어 | Python 3.10 |
| 가상환경 | conda (`environment.yml`) |

### 2.3 데이터 관리 원칙
- `data/raw/`는 **읽기 전용**이다. 원본은 절대 수정하지 않는다. 엑셀 원본도 CSV로 바꿔 저장하지 않고, 코드로 processed CSV를 만든다.
- `data/raw/`는 출처별 하위 폴더로 나눈다: `public/`(공공데이터), `distribution/`(유통처리 엑셀), `jasdc/`(자동 수집), `jasdc_manual/price_daily·price_monthly_box/`(수동 다운로드).
- 모든 가공은 `src/jeju_citrus/data/`의 코드로 수행한다. 결과는 `interim/`(중간) 또는 `processed/`(최종)에 저장한다.
- 단위는 컬럼명 접미사로 표기한다. 예: `_톤`, `_원_kg`, `_원_5kg`, `_백만원`, `_퍼센트`

## 4. 데이터 품질 이슈 (EDA 결과)

`notebooks/01_eda.ipynb`에서 발견한 이슈입니다. 정제 코드는 `src/jeju_citrus/data/clean_quality.py`, 확인 근거 표는 `python scripts/check_quality.py`로 다시 볼 수 있습니다.

| # | 데이터 | 이슈 | 처리 방안 | 상태 |
| --- | --- | --- | --- | --- |
| Q1 | noji_* | 연도가 `'2025년산'` 같은 문자열 | `parse_crop_year()`로 정수 변환 | ✅ |
| Q2 | noji_monthly, varieties | `계`/`소계` 합계 행이 개별 항목과 혼재 | `drop_total_rows()`로 제거 | ✅ |
| Q3 | varieties_summary | `*_증감률_퍼센트`가 실제로는 **전년 대비 비율**(101 = +1%). 원본 사이트 표의 `대비(%) (A/B)` 열을 옮기면서 이름이 잘못 붙음 | 원래 값은 `*_전년비_퍼센트`로 이름 변경, `*_증감률_퍼센트`는 2025·2024 원값으로 다시 계산(소수 1자리) → `interim/varieties_summary_clean.csv` | ✅ |
| Q4 | fruit_production | 같은 품종이 연도별로 다른 대분류에 속함. 확인해 보니 2016년부터 **레드향(→기타)과 단감(→만감류)의 대분류가 서로 뒤바뀌어** 있고, 2015년 만감류 기타는 `만감류/기타`로 적혀 있음. 또 `만감류` 품종 행은 `감귤`의 만감류노지+하우스를 다시 나눈 것이라 함께 더하면 **이중 집계** | `FRUIT_CATEGORY_MAP`으로 대분류 통일, `집계수준` 컬럼 추가. 보정 후 6개 연도 모두 만감류 품종 합계 = 만감류노지+하우스(차이 0.04% 이내, `validate_fruit_hierarchy()`) | ✅ |
| Q5 | jeju_special_crops | 중복행 1건, 단수 결측 6건, 단수 0값 57%, 극단값(최대 21,008). 확인 결과 결측 6건은 2023년에만 있는 **품목군 소계 행**(유지작물 = 유채+참깨+땅콩+들깨 등), 0값은 2018년부터 전국 품목을 모두 싣으면서 생긴 **제주 미재배 행**(404행), 극단값은 수확면적 2ha를 반올림한 데서 생긴 값 | 중복·소계·미재배 행 제거(758 → 349행), `단수_계산_kg_10a = 생산량×100÷수확면적` 추가, 단수 0인데 생산량이 있는 6건은 결측 처리, `단수_이상`에 버섯(단위 다름)·소면적(<3ha)·원본·계산 50% 초과 차이 표시, 같은 해 여러 번 나오는 `기타`는 `기타_1`·`기타_2`로 구분 | ✅ |
| Q6 | 전체 | 생산 통계(2015~2020)와 유통 통계(2021~2025)의 기간이 겹치지 않음 | `citrus_production_yearly`(2004~2025)로 대체 | ✅ |
| Q7 | noji_monthly vs noji_yearly | 월별 출하량 합계(21.8만 톤)가 연간 처리량(41.1만 톤)의 약 53% | **확인 완료:** 월별 표는 일별 표의 도매시장+직거래 출하 합계와 같다(218,236톤 vs 218,235.9톤). 연간 처리량은 가공·도내 소비 등까지 포함한 전체 물량. 출하비율은 5개 시즌 모두 45~53%로 안정적 → 두 표를 섞지 말고 `출하비율`로 연결 | ✅ |
| Q8 | citrus_production_yearly | 15개 행에서 `단가`가 `조수입 ÷ 생산량`과 5% 넘게 어긋남 | **확인 완료:** 단가는 `조수입 ÷ 유통 처리량`이다. 2024년 7개 품종 모두 유통처리 엑셀의 처리량으로 나누면 1원 단위까지 일치. `처리량_추정_톤`·`단가_검증`(일치 120 / 처리량기준 13 / 확인불가 4) 컬럼 추가. ha당 조수입은 조수입을 그대로 쓰므로 영향 없음 | ✅ |
| Q9 | citrus_production_yearly | 황금향 2014 단가 `6,375`(계산값 2,556원), 황금향 재배면적 2016→2017년 98→351ha 급증 | **확인 완료:** ① 2014 단가로 거꾸로 구한 처리량이 생산량의 40%(988톤)라 처리량 기준으로도 설명이 안 됨 → `단가_검증=확인불가`, 단가 분석에서 제외. ② 2017년 면적 급증은 황금향만의 일이 아니라 **통계 단절**: 노지온주 -10%·월동온주 -33% 면적이 줄고 레드향 +338%·천혜향 +152%·황금향 +258%가 늘었는데 생산량은 거의 그대로(`structural_break()`). 2016↔2017년 사이의 면적·ha당 생산량은 비교하지 않는다 | ✅ |
| Q10 | jasdc vs noji_yearly | jasdc의 노지온주 **생산량**(2024년 371,916톤)과 `noji_yearly`의 **처리량**(369,145톤)은 서로 다른 지표 | 컬럼명으로 구분하고 섞어 쓰지 않음 | ✅ |
| Q11 | citrus_price_daily vs citrus_price_monthly_box | 2024년 10월 도매 출하량(일별 20,490톤)이 월별 거래량(11,699톤)의 약 1.75배 | **확인 완료:** 가격은 같은 출처(월별 평균가 ÷ 일별 도매 가중평균가 = 0.995~1.004). 물량은 월별 표가 전체 도매 출하의 53%(월 32~57%)로, 9대 도매시장 합계 비율(2025년산 58%, 가격비율 0.999)과 비슷 → 월별 상자규격 표는 주요 도매시장 경락 기준. 가격은 두 표를 섞어 써도 되지만 물량은 섞지 않는다 | ✅ |

| 시장·규격별 가격 | 월별 상자규격 표와 9대 시장 표는 일별 도매가와 가격이 같음(Q11) | 가격은 함께 써도 됨, 물량은 표마다 따로 |
